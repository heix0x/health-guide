# 根项目是健康指南，两本书平级

根目录原来是一本书（《高中生身体健康指北》），烟只是它下面的一个文件夹。这让烟的读者以为它是学生读物，也让两本书的文档、产物和构建脚本混在一起。

现在根项目只做索引：两本书各占一个目录，各有 README、CHANGELOG、docs 与构建脚本；通用的只有 `AGENTS.md`、`GLOSSARY.md` 和结构 ADR。

**考虑过的方案**

- 保持附件式：改动最小，但「烟是学生书」的误读会一直存在。
- 拆成两个仓库：隔离最彻底，但两本书共享同一套写作约定，拆开后约定会漂。
- 一个仓库、两个平级子项目：选这个。

**代价**

- 所有路径变了，根目录不能再双击 `index.html`。
- 构建脚本各一份，有重复；换来的是改一本书不会碰另一本。
- 文档要分层：通用的放根目录，每本书自己的台账放各自目录，不许互相复制。
