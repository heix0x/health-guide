# 待办：把仓库目录改名为 `health-guide`

**结论：可以改。项目文件不会丢，Git 历史也不会丢。但对话记录是按「绝对路径」存的，改名后可能在新项目下看不到——文件还在，只是入口变了。**

---

## 不会丢的

- 项目里的所有文件、两本书的源文件与 PDF。
- Git 历史：`.git` 在目录内部，跟着目录一起改名。
- 项目内记忆：`.workbuddy/memory/` 也在目录内部。
- `student-health/docs/资料库/` 里的私人素材（不进版本库，但在磁盘上）。

## 会受影响的

### 1. 对话记录（最需要注意的一项）

对话记录不在项目目录里，在：

```
C:\Users\<用户名>\.workbuddy\projects\d-project-高中生肠胃护理指南\
```

目录名是「绝对路径 → slug」的结果（`D:\project\高中生肠胃护理指南` → `d-project-高中生肠胃护理指南`）。里面有 5 个会话，每个一对 `.jsonl` + `.file-rollback.ndjson`，合计约 9 MB。

改名后，应用会去找 `d-project-health-guide`，找不到就当成一个全新的项目。**旧的 5 个会话仍然躺在原来的目录里，不会消失，但可能不会出现在新路径的项目下。**

处理办法：改名后，把旧目录**复制**一份、命名为 `d-project-health-guide`，再打开应用看历史是否回来。原件不要删，等验证过再说。

### 2. 当前工作区

IDE、终端、预览进程绑的都是旧路径。改名后必须关闭并重开，否则会报「路径不存在」。

### 3. 快捷方式与外部引用

桌面快捷方式、浏览器收藏、别的脚本里写死的绝对路径，都会失效，需要手动改。仓库内部的路径全是相对的，不受影响。

### 4. Windows 占用

资源管理器、终端、PDF 阅读器、同步盘占着目录时，改名会失败（这次搬 `dist/` 就撞过一次 `Permission denied`）。改名前把这些都关掉。

---

## 操作步骤

1. 完成本轮重构，构建通过，提交。
2. 关闭 WorkBuddy、所有终端、资源管理器里打开的该目录、所有 PDF 阅读器。
3. 备份会话目录：

   ```powershell
   Copy-Item "C:\Users\<用户名>\.workbuddy\projects\d-project-高中生肠胃护理指南" `
             "C:\Users\<用户名>\.workbuddy\projects\d-project-高中生肠胃护理指南.bak" -Recurse
   ```

4. 在资源管理器里把 `高中生肠胃护理指南` 改名为 `health-guide`。
5. 复制一份会话目录并改成新 slug：

   ```powershell
   Copy-Item "C:\Users\<用户名>\.workbuddy\projects\d-project-高中生肠胃护理指南" `
             "C:\Users\<用户名>\.workbuddy\projects\d-project-health-guide" -Recurse
   ```

6. 重开 WorkBuddy，打开 `D:\project\health-guide`，检查三件事：
   - 历史会话是否出现；
   - 两本书能否各自构建；
   - `git status` 是否正常、历史是否完整。
7. 若历史没出现：删掉第 5 步复制出来的目录，保留原件；旧记录始终在 `.bak` 和原目录里，最坏的情况只是「不能在界面里直接翻到」。

## 建议

不急。等两本书的内容都稳定了再改——改名本身只要五分钟，真正的成本是重开会话和验证。改之前把 `.bak` 留着，至少放一个月。
