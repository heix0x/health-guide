## 一、分支

**只在 `main` 上写，不建分支。**

分支是给多人并行和线上灰度用的。这里是一个人、两本书、没有发布回滚需求。开分支的真实后果是：改完忘了合，第二天在旧分支上继续写，制造一次没人看得懂的合并。

唯一值得开分支的情况：要做一个**不确定能否成立**的大改动（比如整本重写），且期间还得继续定版。做完合回或者丢掉，别留超过一周。

## 二、提交粒度与信息

一次提交只做一件事，且**尽量只动一本书**。两本书同时改，就拆两个提交——这样回滚一本时不会连累另一本。

格式：`type(scope): 中文描述`

| 字段 | 取值 |
| --- | --- |
| type | `feat` 新增内容/功能 · `fix` 修正错误 · `docs` 文档与约定 · `refactor` 结构调整 · `build` 构建脚本与产物 · `chore` 杂项 |
| scope | `student-health` · `smoke` · `repo`（仓库级）· `portal`（索引页） |

```
fix(student-health): 第三章睡眠时长改回「七到九小时」
docs(repo): 新增部署与版本管理两份文档
build(repo): 组装脚本加空白页与外部引用检查
refactor(repo): 拆成健康指南仓库，两本书平级
```

描述写**做了什么、为什么**，不写「修改了一些内容」。半年后唯一能依靠的就是这一行字。

## 三、PDF 与 public/ 怎么进库

| 目录 | 进不进库 | 规则 |
| --- | --- | --- |
| `student-health/index.html`、`smoke/index.html` | 进 | 唯一源，一切改动从这里开始 |
| `*/dist/pdf/` | 进，但**只在定版提交** | 19 份，约 6.7 MB |
| `public/` | 不进 | `.gitignore` 已排除，`assemble_public.py` 每次重建 |
| `*/docs/资料库/` | 不进 | 真实姓名、QQ 号 |
| `.workbuddy/`、`.wbapp_*.genie`、临时截图 | 不进 | |

**「只在定版提交」是什么意思**：一次定版 = 一个提交，里面同时有正文、重新生成的 PDF、CHANGELOG 条目、版本号。两次定版之间的小修可以有好几个提交，只动 `index.html`，**不重出 PDF**。

理由是两头都要顾：每次改一个错别字就重出并提交 6.7 MB 二进制，是在拿 Git 当网盘；而完全不存 PDF，则交付物不可追溯——PDF 能重建，但重建不一定一模一样（字体、分页引擎的版本都会影响）。

代价要认：`dist/pdf/` 对应的是**最近一次定版**，不保证与 `HEAD` 的正文逐字一致。想拿和当前正文严格对应的 PDF，跑一遍 `build_pdfs.py`。这句话写在这里，就是为了以后不把它当 bug 查。

## 四、版本号与 tag

两本书各有版本号（见各自 CHANGELOG），仓库也有。一个 Git 只有一套 tag 命名空间，所以带前缀：

```
student-health/v0.11
smoke/v1.0
repo/v2.1
```

- tag 打在**定版提交**上，用附注 tag：`git tag -a smoke/v1.0 -m "一根烟的事 v1.0：23→22 页，删自证段"`
- `repo/*` 只给结构变更打，不给内容变更打。
- 两本书的版本号不必同步。仓库版本只在目录结构、共用约定变化时 +1。

## 五、远程与备份

**这是目前唯一的严重风险：没有任何远程仓库。**

建议：建一个**私有**仓库（GitHub / Gitee / 自建都行），`git remote add origin …`，`main` 推上去，顺手 `git push --tags`。私有是因为 `docs/` 里的决策台账提到过素材的来源与场景，虽然正文已匿名化，但没有必要公开。

开公开仓库之前必须做一遍历史扫描，别只看当前文件：

```bash
git log -p --all | grep -nE "[0-9]{5,12}" | head -40     # QQ 号、手机号
git log -p --all | grep -nE "同学|真名" | head -40
```

一旦带着敏感内容推上去，删除文件是没用的——历史还在，任何一次 clone 都能翻出来。真发生了，只能用 `git filter-repo` 重写历史并强推，那是一次真正的破坏性操作。

## 六、提交前 30 秒

1. `git status --short`——**里面出现 `public/` 或 `资料库` 就停下来**，说明忽略规则失效了。
2. 只改了一本书？确认提交里没有另一本的 `index.html`。
3. 这次是定版吗？是 → PDF 重出过了吗，CHANGELOG 和版本号改了吗，tag 打在哪。
4. 改的是正文 → 线上要不要跟着变（见 [`部署与发布.md`](部署与发布.md)）。

## 七、不要做的事

- **不要 `git add -A` 之后就提交**，尤其在有临时截图、`public/`、别人的素材目录时。看得见的提交，好过事后 `filter-repo`。
- **不要 amend 已经推上去的提交**，也不要对 `main` 强推。
- **不要在提交里塞两本书的改动**，回滚时会一起回滚。
- **不要把 PDF 的改动单独提交**，它脱离了对应的正文就没有意义。
