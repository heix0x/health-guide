## 为什么是 public/

仓库根目录不能直接发布：`*/docs/资料库/` 里有真实姓名、QQ 号和聊天原文，会跟着上传。`public/` 里只有三个 `index.html`，没有别的。

```
portal/index.html             索引页（源，手写）
student-health/index.html     书（源）
smoke/index.html              书（源）
        ↓  python tools/assemble_public.py
public/index.html             索引（产物）
public/student-health/index.html
public/smoke/index.html
```

`public/` 每次清空重建，**不要手改**。手改的东西下一次就没了。

`public/index.html` 与 `portal/index.html` 内容逐字相同，这是正常的：前者是后者的副本。同理，`public/<书>/index.html` 与 `<书>/index.html` 也完全相同。**三个文件在 `public/` 里没有一个是原件**——原件在 `portal/` 和两个书目录里，`public/` 只是为了让发布工具有一个「干净、不含资料库」的上传目录。

判断该改哪个：想改线上内容，改原件；改完 `public/` 里那份会自动更新。改 `public/` 里的东西，在下一次组装时被覆盖，且不会进库（`.gitignore` 已排除），等于白改。

## 发布

```bash
python tools/assemble_public.py     # ① 组装，顺带做检查
```

脚本会拦三种情况：页面小于 20000 字符（被截断）、没有内联样式（样式被拆出去了）、引用了外部资源（静态托管下会失效）、书页找不到 `#ch1` 锚点（不是正文页）。任何一条不通过，`public/` 不会生成，不会带着坏页面上去。

② 确认 `public/` 里是三个文件、体积正常（两本书各约 84 KB）。

③ 以 **`public/` 为目录**发布。发布是覆盖：链接不变，线上换成新的。

④ 打开三条地址各看一眼。**别只看「发布成功」**——发布成不成功和内容对不对是两件事。

## 改完内容之后

顺序不能反：

1. 改 `student-health/index.html` 或 `smoke/index.html`
2. 要出 PDF 的话，先 `cd <书>/ && python tools/build_pdfs.py`
3. `python tools/assemble_public.py`
4. 发布
5. 抽一页线上内容读

漏掉第 3 步，线上还是上一版。这不是 bug，是「产物不是源」的必然结果（AGENTS.md 第 12 条）。

## 线上不放的东西

- **PDF**：`dist/pdf/` 一共 19 份、约 6.8 MB。不放上去的理由是**没有入口**——线上读者要的是「现在查一段」，不是「下载一份 22 页的册子」；硬加下载按钮要在单文件里写死 9 个文件名，每次重出 PDF 都得手工核对一遍。要纸质版走「打印全册」，要文件找本地。
- **PDF 却放在 `public/` 之外**：即使哪天要放，也走 `assemble_public.py` 加一步复制，不手塞。
- **资料库**：永不。
- **docs/、tools/**：不发布，不解释。

## 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「链接不完整」 | 少了 `?sharecode=` | 用完整链接；索引页的入口靠脚本带参数，别删那段脚本 |
| 点索引页的书没反应 | 同上，或浏览器禁了 JS | 直接把子路径的完整链接给对方 |
| 线上还是旧内容 | 忘了跑 `assemble_public.py` 或忘了发布 | 重跑 ①②③ |
| 页面白屏 | `index.html` 引用了外部资源 | 跑脚本，它会报出来 |
| 两本书互相串了 | 发布时目录选成了子目录而不是 `public/` | 重新以 `public/` 发布 |

## 一条判断

发布前的验证只有一句话：**随机抽一页线上内容，读一遍。**

页数、体积、「发布成功」、HTTP 200，都是形式。形式对了不等于对了（AGENTS.md 第五节的题记）。
